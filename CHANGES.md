# Changes in this build

1. **Dashboard "Database file 0 B"** - the code looked for a SQLite file, but the app uses MySQL. The card is now "Database size" and reads data+index size from MySQL (SQLite still supported).
2. **"Backups per day: No backups"** - the query used `ts__date` / `TruncDate`, which on MySQL needs the time-zone tables (otherwise NULL, empty chart). Days are now grouped in Python.
3. **Backups started late** - the old job pinged the *whole* inventory (and resolved DNS one by one) before the first SSH login. Now ping and SSH are a pipeline: each device is queued for SSH the moment it answers. Offline devices never occupy an SSH worker.
4. **Slow dead devices** - a silent SSH device is retried once (was 3x30 s).
5. **"Devices online" graph dips** - ping defaults are now 2 attempts / 1.5 s, and failed hosts get a second round (with a 3 s pause if >40% fail at once).
6. **Day shows no data in the Backups tree** - an UNCHANGED check overwrote the day's `run.json` (SUCCESS). A saved snapshot's record is now kept; `run.json` is written atomically.
7. **Log/DB write can no longer turn a good backup into FAILED** - names are cut to 100 chars (MySQL strict mode), DB errors in `record()` are logged, not raised.
8. **MySQL stability** - `CONN_HEALTH_CHECKS`, connect/read/write timeouts, job progress writes retry after a dropped connection.
9. **Ready to publish** - no password or IP is stored in the code any more: `DBMS_DB_PASSWORD` is required in `.env`, and `DJANGO_ALLOWED_HOSTS` (your public IP/domain) also goes in `.env`.
10. **Code cleanup** - shared helpers instead of copies (`get_json_list`/`get_id_list`/`set_pending_devices`, `_atomic_write_text`), dead `_ensure_enable_mode` and unused imports/variables removed.
11. Default `WORKERS` 5 -> 10. Tests updated/added (65 pass).

Do NOT overwrite your existing `data/` folder (it holds `secret.key`).
After copying, restart the service. Static files were already rebuilt in `staticfiles/`.
11. **RADIUS Admin merged in** - the separate RADIUS panel is now the `apps/radius` app. Administrators get a "RADIUS Admin" drop-down in the side menu (Users, Devices (NAS), Audit). It uses a second database connection (`RADIUS_DB_*` in `.env`) and the normal sign-in of this application. See "RADIUS Admin (merged)" in the README.
12. **"A backup is already running" can no longer get stuck** - a running job writes a heartbeat; a job left behind by a restart or crash is closed after 3 minutes without one (was 24 hours). The Devices page now shows a "Backup running: X of Y devices done" bar for any running job (also after a page refresh, or when the schedule or another user started it) with a **Stop backup** button for operators and administrators. Devices whose SSH session hangs past every timeout are marked failed instead of holding the job open forever.
13. **500 devices in one backup** - "Back up all" runs the whole inventory as one job. Parallel SSH sessions can now be set from 1 to 50 on the Settings page (was effectively 15).
14. **Code cleanup** - no password or server IP is left in `config/settings.py`: `DBMS_DB_PASSWORD` and `DJANGO_ALLOWED_HOSTS` must be set in `.env`. The duplicated database block is one clear `mysql` / `sqlite` switch (`DBMS_DB_ENGINE`, default `mysql`). The Users page Edit / Delete buttons no longer use inline `onclick`, which the Content-Security-Policy blocks. A start-up error in the browser console (`dashTimer`) is fixed. Old log files and a stray file were removed from the source.
15. **New sign-in and first-run setup page** - same navy and indigo as the rest of the application, a short description of the system, a notice after an automatic sign-out for inactivity, dark mode and a phone layout.
16. **RADIUS users per switch** - the user pop-up has "Where this user can log in": all devices, or selected switches only. Network entries cannot be picked one by one. A failed audit-log write no longer hides or repeats the real change. (Storage changed in item 20.)
17. **Review pass: security and tidying**
    - RADIUS shared secrets are no longer sent with the device list; one is fetched only on Show / Copy and the request is audited. A typed secret needs 12+ characters, and the same IP / network cannot be added twice.
    - Optional `RADIUS_PASSWORD_MODE=ssha2` (salted SHA-256 instead of clear-text RADIUS passwords) and `DBMS_REVEAL_PASSWORDS=0`.
    - `DBMS_ALLOWED_NETWORKS` works again as an optional allow-list for SSH and ping targets; `manage.py show_network_policy` no longer crashes.
    - CSV exports neutralise cells that a spreadsheet would run as a formula. Bulk import skips loopback / special-use addresses. Two endpoints answered 500 on malformed input and now answer 400.
    - New `manage.py radius_init`, `deploy/dbms.service` and `deploy/nginx-dbms.conf`; the README no longer points at files that do not exist and states Python 3.10+.
    - The RADIUS pop-ups show the database error instead of opening with empty lists.
18. **Browser code split into named files** - `static/js/app.js` is now one file per page (`helpers.js`, `menu.js`, `dashboard.js`, `devices.js`, `backup-jobs.js`, `backups.js`, `logs.js`, `users.js`, `settings.js`, `radius.js`, `start.js`) and `static/css/app.css` is `base.css`, `pages.css`, `theme.css`, `refinements.css`, `radius.css`, `backup-jobs.css`. A final style layer (`design.css`) flattens the cards, quiets labels and filter chips, and evens out the statistic tiles. The system-health figures are one divided panel instead of cards inside a card.
20. **Fix: a user limited to selected switches could not log in anywhere** - the limit was stored as a `radcheck` row `NAS-IP-Address =~ ^(...)$`. FreeRADIUS 3 cannot read a regular expression for an IP-address attribute from SQL, so the whole user failed to load and every login was rejected, on the chosen switch too. The limit is now one row per switch in a new `dbms_user_nas` table, checked by a small FreeRADIUS policy (`deploy/radius/dbms_device_limit`) against the address the request comes from. There is no longer a limit of about 11 switches per user. After updating: run `manage.py radius_init` (creates the table and moves the old rows out of `radcheck`, which immediately lets those users log in again), then install the policy once as described at the top of that file and restart FreeRADIUS.

21. **Redesigned, fully responsive interface** - the eight layered stylesheets (`base.css` ... `design.css`) are replaced by one design system, `static/css/app.css`: colour tokens for light and dark mode, a blue-to-cyan network theme, a dark side menu, a frosted top bar, statistic tiles with accent bars, animated charts (first draw only, so the 30-second refresh never flashes), and smooth page, pop-up and menu transitions (switched off for people who prefer reduced motion).
    - Layout adapts at 1280 / 1024 / 760 / 480 px: the side menu becomes a slide-out drawer on tablets and phones, every page fits without sideways scrolling, buttons and fields are touch-sized, and pop-ups open as bottom sheets with a fixed Save bar on phones.

22. **A backup changes nothing unless it completed** - previously the configuration file was written straight to its final name (a crash mid-write left a half file that became "latest"), it was saved *before* the database record, a database error after that was silently ignored, and an SSH session still running when someone pressed **Stop backup** could save a file and mark the device "Saved" minutes later.
    - A completed backup is now one unit: the configuration is written to a hidden temporary file, then the log line, the device status / name and the rename of the file into place happen in ONE database transaction. If any step fails, the transaction is rolled back and the file is deleted, so either everything is saved or nothing is.
    - A backup that did not complete (offline, login refused, SSH dropped, read timeout, command rejected, database error) never saves a file and never changes the device name or its saved configurations; only the failure is logged, with the FAILED status.
    - Stop backup / a hung job now signals every running device: a session that answers afterwards discards what it read and writes nothing at all.
    - Failure messages are written for people: what happened, that nothing was saved, and what to check (for example "Login failed: the device rejected the username or password ... Nothing was saved.").
    - New tests cover a database failure (no file left behind) and a session finishing after Stop backup (nothing written).

56. **Patient, self-healing backups** (docs/BACKUP_RELIABILITY.md) - a slow device is no longer cut off after a fixed 300 s: VAULT keeps waiting while the device sends its configuration and gives up only when it has been silent for 180 s (DBMS_COMMAND_IDLE_SECONDS), with a 1-hour safety ceiling (DBMS_COMMAND_TIMEOUT). A slow SSH login gets one more try with double the time. New SSH logins start at most every 0.5 s (DBMS_LOGIN_SPACING), so 80+ devices no longer knock on their AAA / RADIUS server in the same second - the cause of the few devices that failed in a big run and worked when run again. Every failure gets a kind: offline, temporary, login rejected or permanent. Temporary failures and rejected logins get an automatic second try in the same job (after 60 s, 3 sessions, logins 3 s apart); a device that then works shows 'Succeeded on the automatic second try'. Afterwards, for every job (manual too): offline devices wait in the retry queue and are backed up as soon as they answer ping (up to 7 days); temporary failures are retried after 10 min, 30 min and 2 h; a rejected login once after 15 min (no account lock-out); permanent failures need a person. Nothing reaches the database before a device's outcome is final: a failure held for the second try is written only if that try fails too. Backup Jobs shows 'Waiting to retry' (device, why, tries, since, next check) and the job chip shows the second try. New devices' first backups no longer wait behind the retry queue.
